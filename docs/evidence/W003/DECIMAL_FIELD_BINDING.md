## Pinned behavior and GoEF contract

EF Core v10.0.15 at `b34c0e9d7e768aa808ded44f19e7f871bea6869f` records precision and scale as explicit property metadata before passing them to relational type mapping. The property tests reject setter calls after model freeze. Code First in GoEF accepts the precision and scale pair as one fluent declaration. Repeated matching pairs agree and contradictory pairs report their option positions. GoEF requires explicit facets and delegates fixed-scale conversion to the existing decimal codec. This is an independent Go implementation based on the public contract. [Property builder](https://github.com/dotnet/efcore/blob/b34c0e9d7e768aa808ded44f19e7f871bea6869f/src/EFCore/Metadata/Builders/PropertyBuilder.cs) · [Relational mapping](https://github.com/dotnet/efcore/blob/b34c0e9d7e768aa808ded44f19e7f871bea6869f/src/EFCore.Relational/Storage/DecimalTypeMapping.cs) · [Property tests](https://github.com/dotnet/efcore/blob/b34c0e9d7e768aa808ded44f19e7f871bea6869f/test/EFCore.Tests/Metadata/Internal/PropertyTest.cs) · [MIT license](https://github.com/dotnet/efcore/blob/b34c0e9d7e768aa808ded44f19e7f871bea6869f/LICENSE.txt)

The mapped and physical version 1 snapshots keep a `decimal` member with the configured precision and scale, including zero scale. The byte regression case compares non-decimal snapshots to version 1 fixtures. `BindTypes` resolves `Decimal` and `*Decimal` with explicit facets. A direct pointer accepts SQL NULL. The field codec handles present values, rejects lossy or out-of-range conversions, and preserves fixed scale. Callers choose dialect parameter and text-readback expressions. The prior provider research, limits, driver pins and column evidence apply to the same underlying declarations and codec. [Explicit SQL decimal types and evidence](DECIMAL_SQL_BINDING.md)

## Reproduce

- On baseline `dc13ff64370f7e7348f0f7958dbf996819177a90` with the new Go tests, `go test -mod=readonly -count=1 -run '^(TestDecimalFieldsMODEL_TYPE_001S0[56]|ExampleDecimalPrecision)$' ./model` exited 1. The required declaration and codec accessors did not exist.
- Before adding the field-marker checks to the Python runners, `python -B -m unittest test_driver_run.DecimalBindingEvidenceTests` in `test/conformance/lab` exited 1. A result without field evidence was accepted by the driver runner and the compatibility report lacked the field results.
- Run the same Go and Python commands after implementation. The unit model probe exercises all four dialects without a connection. The runnable example uses Go 1.27.4.
- Run `python -B test/conformance/lab/driver_run.py <provider> --profile <profile> --decimal-binding` on a selected isolated server profile and `python -B test/conformance/lab/sqlite_compat.py --decimal-binding` for both linked SQLite runtimes. The result must contain a verified `decimal_field_binding` marker for S05. The SQL Server lab requires its matching Developer consent switches.
- Run `pwsh -NoProfile -File scripts/ci/goef-w002.ps1 -Compatibility -DecimalBinding -AcceptSqlServerEula -AcceptLegacySqlServerEula` after approval to verify the full profile matrix. The fixture owns the temporary database and uses separate writer and observer leases. It verifies SQL NULL, signed values, the exact precision boundary and scale, and native catalog nullability.
