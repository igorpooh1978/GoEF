# LINQ source inventory

The [operator registry](../parity/linq-operators.json) identifies 1,287 declarations in 627 source-specific member families. This is source discovery at the pinned commits. No GoEF execution, upstream differential run or database capability is certified by these counts. [Tracking issue #4](https://github.com/igorpooh1978/GoEF/issues/4)

| Source and surface | Member families | Overloads | What the count includes |
| --- | ---: | ---: | --- |
| .NET v10.0.0 · Enumerable | 74 | 228 | Every public static method declared on Enumerable in the pinned reference assembly source |
| .NET v10.0.0 · Queryable | 63 | 168 | Every public static method declared on Queryable, including indexed and comparer forms |
| .NET v10.0.0 · Expressions | 200 | 406 | Directly declared public methods on classes in the System.Linq.Expressions namespace plus protected visitor hooks on ExpressionVisitor |
| EF Core v10.0.15 · query extensions | 107 | 302 | Core/relational/Cosmos query extensions, EF query markers and compiled queries, DbFunctions extensions, SQL Server temporal DbSet operations and relational SqlQuery/SqlQueryRaw |
| go-linq v5.0.0 | 76 | 76 | All exported package functions and methods on exported receiver types in non-test Go files |
| go-linq research snapshot | 107 | 107 | Same counting rule at the separate research SHA |

The two Go snapshots share 76 declarations with matching normalized signatures. Counting each snapshot preserves release provenance. The resulting counts are unsuitable as a denominator for implemented semantic equivalents. An integer Average, an indexed Select and a nullable Sum each retain their own signature identity. Separate member rows for Objects and Queryable keep execution modes distinct. Properties, constructors, enum values, inherited framework methods, non-visitor protected methods, the DLR namespace, async-enumerable extensions and third-party provider-specific extension inventories are outside this scan. Navigation and correlated queries are composed shapes that need separate EF model/provider fixtures. Track those gaps and unclassified overload applicability in [issue #4](https://github.com/igorpooh1978/GoEF/issues/4).

### Observations at the pinned commits

* **Enumerable.** A filter selects by a callback and can stop after the consumer has enough matches. Indexed and non-indexed signatures have separate declarations. The source includes left and right joins, finite and infinite sequences, grouping counts and Shuffle. The reference class has no FullJoin method. A range-based Take is an overload of Take, and three-sequence zip is an overload of Zip. [Reference surface](https://github.com/dotnet/runtime/blob/60629d14374c56f1cb51819049ad1fa529307f8d/src/libraries/System.Linq/ref/System.Linq.cs) · [Where implementation](https://github.com/dotnet/runtime/blob/60629d14374c56f1cb51819049ad1fa529307f8d/src/libraries/System.Linq/src/System/Linq/Where.cs) · [early-stop fixtures](https://github.com/dotnet/runtime/blob/60629d14374c56f1cb51819049ad1fa529307f8d/src/libraries/System.Linq/tests/ShortCircuitingTests.cs)
* **Queryable.** Where constructs a call expression, quotes the predicate and asks the source provider to create a query. The pinned tests exercise overloads and null argument validation. An in-memory query provider can execute some of these tests without touching a relational engine. [Reference surface](https://github.com/dotnet/runtime/blob/60629d14374c56f1cb51819049ad1fa529307f8d/src/libraries/System.Linq.Queryable/ref/System.Linq.Queryable.cs) · [Where construction](https://github.com/dotnet/runtime/blob/60629d14374c56f1cb51819049ad1fa529307f8d/src/libraries/System.Linq.Queryable/src/System/Linq/Queryable.cs#L48) · [Where tests](https://github.com/dotnet/runtime/blob/60629d14374c56f1cb51819049ad1fa529307f8d/src/libraries/System.Linq.Queryable/tests/WhereTests.cs)
* **Expressions.** The reference distinguishes typed parameters, constant factories, lifted binary expressions and visitor hooks. The larger surface includes mutation, dynamic dispatch and local compilation. GoEF's proposed subset needs type/owner checks and a registered-call model. Applicability of the remaining factories stays open. [Reference surface](https://github.com/dotnet/runtime/blob/60629d14374c56f1cb51819049ad1fa529307f8d/src/libraries/System.Linq.Expressions/ref/System.Linq.Expressions.cs) · [constant factories](https://github.com/dotnet/runtime/blob/60629d14374c56f1cb51819049ad1fa529307f8d/src/libraries/System.Linq.Expressions/src/System/Linq/Expressions/ConstantExpression.cs) · [nullable constant tests](https://github.com/dotnet/runtime/blob/60629d14374c56f1cb51819049ad1fa529307f8d/src/libraries/System.Linq.Expressions/tests/Constant/ConstantNullableTests.cs)
* **EF Core.** Include, filter modes, tracking, async terminals, bulk delete/update and raw SQL introduce model, command and ownership semantics. Database/CLR collation and null semantics require matched provider/version runs. The query registry also retains the Cosmos-specific source rows for applicability review. [Core extensions](https://github.com/dotnet/efcore/blob/b34c0e9d7e768aa808ded44f19e7f871bea6869f/src/EFCore/Extensions/EntityFrameworkQueryableExtensions.cs) · [relational extensions](https://github.com/dotnet/efcore/blob/b34c0e9d7e768aa808ded44f19e7f871bea6869f/src/EFCore.Relational/Extensions/RelationalQueryableExtensions.cs) · [navigation fixtures](https://github.com/dotnet/efcore/blob/b34c0e9d7e768aa808ded44f19e7f871bea6869f/test/EFCore.Specification.Tests/Query/NorthwindIncludeQueryTestBase.cs)
* **go-linq v5.0.0.** Query wraps a native iterator. Where calls the predicate on each demanded element and propagates the yield result. FromMap has no order guarantee. Single returns a single boolean for exact cardinality, which cannot distinguish absent from multiple. The GoEF design calls for that distinction. The migration guide describes exported typed constructors and the removal of reflection-based overloads. ### Reproducing a record

1. Select a row and read its `source` key. Use the repository and exact commit in `sources`. For each overload, join its source repository URL, `/blob/`, SHA, path and `#L` with its one-based declaration line. The recorded signature preserves input, result, generic constraints and null markers. Whitespace is normalized, the function body and C# nullable preprocessor lines are omitted.
2. Group by execution mode, source snapshot, declaring owner and member name. Each overload ID appends the first ten lowercase hex digits of SHA-256 over its normalized UTF-8 signature. Use the signature and commit to reconcile a changed declaration at an upstream update. For the two .NET static classes, counting public static declaration starts within each class gives 228 and 168. For Go, exclude test files and methods on private receiver types such as the internal sorter.
3. Open the named implementation file and the pinned test lead in the same repository. Test leads locate family-level occurrences in source. Each overload still needs an explicitly attributed fixture. Twenty-nine expression families and four EF families lack a direct test lead in this scan. The four EF members are CreateDbCommand, Hex, Substr and Unhex. Empty leads denote research gaps.
4. Read the mode contract, semantic profile and provider policy referenced by the row. The upstream signature is the authoritative input/output reference. A profile sets obligations for the future Go API. The acceptance block records the shared ADR, missing executable examples and pending overload-specific contracts. For each query candidate, select actual supported engine versions before attaching results.
