# Engine version compatibility

[W002 #31](https://github.com/igorpooh1978/GoEF/issues/31) · [Provider matrix](PROVIDER_MATRIX.md) · [Local execution](../../test/conformance/driverlab/README.md)

Record compatibility by engine family, actual server or linked runtime version, selected driver, platform, database compatibility mode and required feature. The provider SPI generation describes the Go execution contract. It does not encode any engine version. Every executable test profile uses an immutable artifact or a locked embedded driver and checks the observed version and settings before writing fixtures.

## Selecting capabilities

- **PostgreSQL.** Read `server_version_num` and select the compatible dialect before emitting or accepting a plan. Keep the SQL in the common profile valid on major 16. Later syntax, server functions and extensions need an explicit capability and a negative test on the lower profile. Record database collation and session settings independently.
- **SQL Server.** Observe product version, edition and actual database compatibility level separately. Set compatibility level explicitly in the test database. Both SQL Server 2022 profiles probe `GENERATE_SERIES` on the same build. The fixture checks that the built-in table-valued function override is absent or off. It expects rows at level 160 and native error `208` at level 140. Confirm encryption and protocol behavior per engine. TDS 8.0 Strict belongs to the later engine profile. Keep certificate trust for disposable loopback fixtures separate from production TLS verification. [GENERATE_SERIES requirements](https://learn.microsoft.com/en-us/sql/t-sql/functions/generate-series-transact-sql?view=sql-server-ver16) · [TDS 8.0](https://learn.microsoft.com/en-us/sql/relational-databases/security/networking/tds-8)
- **MySQL.** `VERSION()` supplies three-part identity for legacy releases. `VERSION_WITH_UPDATE()` was added in 8.4.13 and is required when asserting the selected 8.4.13.1 build. The two current profiles select fixed version probes and fail if the expected identity is absent. Authentication, isolation, InnoDB behavior and constraints need version-specific evidence. MySQL 5.7 lacks 8.0 features such as window functions and atomic DDL. Its narrower capability contract needs its own approval and tests. [Release identity change](https://dev.mysql.com/doc/relnotes/mysql/8.4/en/news-8-4-13.html) · [MySQL 8.0 changes](https://dev.mysql.com/doc/refman/8.0/en/mysql-nutshell.html)
- **SQLite.** Observe `sqlite_version()`, `sqlite_source_id()`, compile options and connection-level settings. Gate generated columns at 3.31.0, `RETURNING` at 3.35.0, STRICT tables at 3.37.0 and JSONB at 3.45.0. File accessibility also depends on the stored schema and encoded values. Verify read, write, upgrade and downgrade using actual older and newer linked runtimes. Run rebuild and rollback tests when an older engine lacks a native schema change. [Generated columns](https://www.sqlite.org/gencol.html#compatibility) · [RETURNING](https://www.sqlite.org/lang_returning.html) · [STRICT](https://www.sqlite.org/stricttables.html) · [JSONB](https://www.sqlite.org/json1.html#jsonb)

Bind validated capabilities to the connection and negotiated plan. Record which profile and implementation branch produced each supported operation. Reject unknown or unavailable features before dispatch with the portable error contract. Emulation needs a reviewed equivalent and outcome tests. Keep legacy dependencies and test data isolated from the primary driver module.
