# Map and load relationships

Status: Proposed. The example is a planned acceptance case and has no runnable GoEF API yet.

Represent dependent foreign keys and principal keys explicitly. A planned customer/order example compares eager and split loading with identity resolution and bounded query counts. An optional relationship preserves an absent principal independently of a zero-value ID.
