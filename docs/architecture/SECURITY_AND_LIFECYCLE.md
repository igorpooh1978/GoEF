# Security and resource lifecycle

Proposed runtime guarantees. The application selects the provider and supplies a runtime credential with only the privileges it needs. Migrations use a distinct identity and explicit execution. Resolve credentials through deployment configuration or a secret provider, and verify the driver's encrypted transport and certificate policy for network connections.

| Resource | Owner and lifetime | Failure handling |
| --- | --- | --- |
| Factory/pool | One shared factory per database/security configuration. Construction declares whether an existing pool is borrowed or transferred. | Factory shutdown stops new contexts and drains or cancels owned work under the caller's deadline. Close an owned pool once. |
| Context | One unit of work. Protect active operations through a busy/closed check. Shared immutable metadata is safe across contexts. | Reject overlap with a typed busy error before driver access. Closing releases owned active resources, leaves a borrowed pool usable, and causes future operations to fail as closed. |
| Stream | The iterator holds rows and the context operation lease during enumeration. Perform I/O with the caller's context. | Close rows and release the lease on exhaustion, cancellation, decode failure or early break. Forward one terminal error while yielding is permitted. A cleanup error after a consumer break uses a redacted diagnostic channel. |
| Transaction | The creator owns commit/rollback, except where an explicit transfer is permitted. All commands use the bound connection. | Preserve the primary error across cleanup. Distinguish confirmed rollback, committed and unknown commit. An uncertain outcome requires reconciliation before replay. |
| Cache/background work | Bound entries by size and lifetime. Partition by model/provider/security-relevant shape. Each worker has an owner, cancellation and a join point. | Release per-context values after the operation. Context pooling requires verified reset of identity map, pending transaction, interceptors, filter values and connection state. |

Typed data inputs become parameters. Resolve column and table identifiers against the frozen model, then quote each component through the provider. Sort direction, operators and functions use enumerated or registered alternatives. Raw SQL requires a separately named API with an explicit argument list. A dynamic user predicate composes inside the mandatory tenant/global scope. Any authorized filter bypass needs an explicit privileged path with audit evidence.

Omit bind values, connection strings, credentials and full free-form SQL from default errors, logs, tracing and metrics. Include a stable operation/feature identifier, phase, provider and safe native code. Interceptors receive an explicitly scoped view and must respect context reentrancy. Keep compile caches free of query arguments and tenant principals. Enforce independent limits on connection checkout, query execution, migration locks and cancellation cleanup.

**Verification.** Exercise overlapping operations and a half-consumed stream, cancel before checkout and during rows, measure owned row/connection release, and inject command plus cleanup failures. Execute identical shapes for two tenants with different input values and compare outputs and telemetry. Verify context pool reuse after cancellation and explicit transaction rollback. Test safe identifiers with unusual but legal names. A stream error after partial success must remain visible to the caller. These checks require real providers. [Provider contracts](PROVIDER_SPI.md)
